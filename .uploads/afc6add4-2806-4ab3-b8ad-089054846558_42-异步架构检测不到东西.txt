在 RKNN 多核部署里，纯异步流水线（async run + async outputs）理论上可以提高吞吐，
但实际工程中往往会带来调度不稳定问题。因为 RKNN 驱动内部队列较浅，多 context 异步提交后，
容易出现任务竞争、核心负载不均衡、上下文锁竞争等现象。

实际表现通常是：
* NPU 利用率波动大
* 某些核心 100%，某些核心很低
* FPS 抖动明显
* 延迟不可控
* 队列堆积后整体吞吐反而下降
* 长时间运行容易触发热降频

尤其在“多路视频 + 多 context + 多核绑定”场景下，异步并不一定比同步更快。
因为瓶颈往往不在 `rknn_run` 本身，而是在 CPU 前处理、后处理、内存同步这些阶段。

因此工业上更常见、更稳定的方案是：

* 多 worker + 同步推理
* 每个 worker 独占 context
* context 绑定固定 NPU core
* 用线程数形成 pipeline overlap

也就是“同步执行、并行调度”，而不是“单 context 深度异步”。这种方案通常更稳定、更容易控延迟，
也更容易把 NPU 利用率提升到 80% 以上。
