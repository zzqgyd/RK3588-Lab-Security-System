2.1 项目深挖生死关，一面二面都绕不开

「介绍一下你认为最复杂的项目」牛客·大厂面经7 / 已意向面经
答题结构（先总后分，3 分钟内）：一句话定位（场景 + 规模 + 结果）→ 画架构图（四进程 + 8 条 IPC 通道）→ 点明我负责的模块（视频链路 / IPC / Qt 显示）→ 主数据流（8 路 RTSP → 硬解 → NPU 推理 → 录像/显示）→ 收尾抛一个量化数字。留钩子引导面试官往你准备最充分的模块追问。
「项目里最有技术含量的部分？为什么不是简单调库？」27届面经
不选业务功能，选性能工程点：零拷贝链路。GStreamer / RKNN / FFmpeg 各自给的是能力，但让 DMA-BUF fd 在三者之间全程不落回用户态拷贝，是自研的胶水工程：gst_dmabuf_memory_get_fd 提取 fd → SCM_RIGHTS 跨进程传递 → DRM_PRIME 喂给编码器——任一环节断链就退化为 memcpy。这正是"调库"与"工程"的区别。
「技术选型做过什么关键取舍？」牛客·大厂面经7
两例：① 解码用 GStreamer、编码用 FFmpeg——GStreamer 对 Rockchip 插件生态完整（mppvideodec 直接输出 DMA-BUF），适合搭多路管线；FFmpeg 对编码参数（GOP / 码率 / Profile）与 MP4 封装控制更细。② IPC 选 Unix Socket 而非共享内存——传的是 fd 不是像素，性能等价，工程复杂度更低（详见 2.2）。
「如果重做，会改进哪些地方？」牛客·大厂面经7 / 27届面经
真实答案（忌空谈"加强学习"）：① 事件解耦——检测状态机与业务响应当前耦合，重做会引入事件总线（这正是我第二个项目 EdgePipe 的出发点，顺势带出项目②）；② 性能埋点——早期没埋延迟/丢帧计数点，后期量化困难；③ 进程监督——加看门狗 / systemd 自动拉起与崩溃恢复。

2.2 Linux 系统编程

「Linux 进程间通信方式有哪些？项目里用了哪种？为什么？」已意向面经·一面
全量：管道 / FIFO、消息队列、共享内存（+信号量）、信号、mmap、socket（含 Unix 域）、eventfd。
项目答：Unix 域 Socket。① 需要传 DMA-BUF fd，只有 SCM_RIGHTS 能在进程间传 fd；② socket 自带消息边界与同步语义，比裸共享内存自管锁简单可靠；③ 传的是 fd（4 字节）不是帧数据（MB 级），性能与共享内存等价。
「select / poll / epoll 的区别？epoll 两种模式？」已意向面经·一面
select：fd_set 位图，默认上限 1024，每次调用全量拷贝进内核，就绪后 O(n) 遍历。poll：pollfd 数组突破 1024 限制，仍全量拷贝 + O(n)。epoll：内核红黑树管理 fd（epoll_ctl 一次注册）、就绪事件挂就绪链表，epoll_wait 只返回就绪 fd，O(1)，海量连接下优势显著。
LT 水平触发：缓冲区有数据就持续通知，编程简单；ET 边缘触发：状态变化仅通知一次，必须配非阻塞 fd + 循环读到 EAGAIN，否则残留数据不再通知。
「进程和线程的区别？项目里怎么选？」CSDN 汇总
进程独立地址空间、隔离性好、创建/切换/IPC 代价高；线程共享地址空间、切换快、需处理同步竞争。项目答：跨功能域（检测核心 / UI / 人脸）用进程——故障隔离，UI 崩溃不拖垮检测；进程内部并发（解码 / 推理 / 录像）用线程 + 队列——共享数据结构方便。
「互斥量和信号量的区别？」27届面经
互斥量：所有权语义，谁上锁谁解锁，可实现优先级继承，用于保护临界区。信号量：计数器，P/V 可由不同任务操作，用于资源计数与任务/中断间同步。二值信号量表象似互斥量，但无所有权、无优先级继承。
「为什么要分用户空间和内核空间？」27届面经
保护与隔离：内核拥有全部硬件权限，用户程序出错不能直接破坏内核与其他进程；靠 CPU 特权级 + 页表隔离。交互必须经系统调用陷入内核，有切换开销——所以高性能设计（零拷贝、缓冲池、mmap）都在减少拷贝与切换次数。
「C 程序运行时的内存分区？」27届面经
.text 代码段（只读）、.data 已初始化全局/静态、.bss 未初始化全局/静态（不占文件体积）、堆（malloc 向上增长，手动管理易泄漏）、栈（局部变量与调用帧向下增长，默认约 8MB）、mmap 映射区（动态库 / 大块分配）。

2.3 C / C++ 基础

「volatile 的作用？局限性？」CSDN 汇总 / 27届面经
禁止编译器把变量缓存进寄存器或重排访问，每次从内存读取。三个场景：MMIO 寄存器、中断与主循环共享变量、多线程共享标志位。局限：不保证原子性、不是内存屏障——需要原子性用 std::atomic 或锁。
「static 的作用？」CSDN 汇总
修饰局部变量：存储期从栈改为静态区，生命周期贯穿整个程序，函数多次调用间保值。修饰全局变量 / 函数：内部链接，仅本文件可见，避免符号冲突。C++ 修饰类成员：类级共享，所有对象一份。
「const 的用法？const + volatile 组合见过吗？」27届面经
const int* p（指向常量，*p 只读）vs int* const p（指针本身只读）vs const int* const p（都只读）；const 成员函数承诺不修改状态。const volatile 组合：只读状态寄存器——软件不能写（const），但硬件会随时改（volatile），嵌入式真实存在。
「C 语言字节对齐的规则？为什么要对齐？」27届面经
规则：成员偏移为其对齐数（通常 = 自身大小）的整数倍；结构体总大小为最大对齐数的整数倍；#pragma pack(n) / __attribute__((packed)) 可压缩。原因：CPU 按字长访问内存，未对齐会拆成多次总线访问，ARM 上非对齐访问甚至直接 fault；DMA、NEON 严格要求对齐。项目场景：网络协议头、硬件 buffer 用 packed 后要防未对齐访问。
「extern "C" 的作用？」27届面经
C++ 为支持重载做了名字修饰（name mangling），extern "C" 让编译器按 C 规则生成符号。C++ 工程调用 C 库（FFmpeg / GStreamer / SQLite 全是 C 库）时，头文件必须包裹，否则链接 undefined reference： 
#ifdef __cplusplus
extern "C" {
#endif
/* C 头文件内容 */
#ifdef __cplusplus
}
#endif
「delete 和 delete[] 的区别？malloc/free 和 new/delete 呢？」27届面经
new[] 必须配 delete[]——逐元素析构；对非平凡析构类型用 delete 只析构首元素（未定义行为）。malloc vs new：malloc 只分配内存、返回 NULL；new = 分配 + 构造 + 失败抛 bad_alloc，类型安全、大小自动推导、可重载（placement new）。

2.4 网络编程

「TCP 和 UDP 的区别？为什么监控场景媒体流用 UDP？」CSDN 汇总
TCP：面向连接、可靠有序、流量 + 拥塞控制、字节流，头部 20B+。UDP：无连接、尽力交付、保留报文边界、开销小延迟低。监控场景答：RTSP 信令走 TCP 保证可靠；媒体流 RTP 默认走 UDP——实时性优先，丢一帧的代价小于重传引入的延迟堆积；穿防火墙场景降级为 TCP interleaved（RTP 打包进 RTSP 的 TCP 连接）。
「三次握手的过程？为什么是三次？」高频
C→SYN(seq=x)；S→SYN+ACK(seq=y, ack=x+1)；C→ACK(ack=y+1)。三次使双方各自确认"我能发你能收、你能发我能收"；两次无法防止网络中滞留的历史重复 SYN 建立无效连接。
「讲一下 TCP 拥塞控制」CSDN 汇总·海康原题
四个算法：慢启动（cwnd 从小值指数增长到 ssthresh）→ 拥塞避免（每 RTT 线性 +1）→ 快重传（3 个重复 ACK 立即重传，不等超时）→ 快恢复（ssthresh = cwnd/2，cwnd = ssthresh 后线性增长）。本质是 AIMD——加性增、乘性减，保证公平与收敛。

2.5 音视频专项海康业务特色，你的主场

「视频编解码了解吗？H.264 和 H.265 的区别？」已意向面经·二面原题
同画质下 H.265 比 H.264 节省约 30–50% 码率。技术差异：宏块固定 16×16 → CTU 最大 64×64 四叉树自适应划分；帧内预测 9 种 → 35 种；新增 SAO 环路滤波；帧间预测与运动补偿更精细。代价：编码复杂度高数倍、专利费用高、老硬件解码不支持。安防现状：H.264 是兼容性基本盘，H.265 在带宽/存储敏感场景普及，海康有 H.265+ 私有码控增强。
「I 帧、P 帧、B 帧和 GOP？」项目必考
I 帧帧内编码，不依赖其他帧，是随机访问与错误恢复的锚点；P 帧参考前向帧做运动补偿预测；B 帧双向参考，压缩率最高，但编解码需等后向参考帧——引入延迟，实时监控常关闭或受限。GOP = 两个 I 帧的间隔：越长压缩率越高，但随机定位粒度粗、丢包后必须等下一个 I 帧才能恢复。
「SPS 和 PPS 是什么？」项目②核心考点
SPS 序列参数集：分辨率、Profile/Level、参考帧数等序列级信息；PPS 图像参数集：熵编码方式、slice 分组等。解码器初始化必需，缺失则关键帧也解不出来。RTP 传输时随 SDP 以 sprop-parameter-sets 带出，或每个关键帧前重发。
「RTSP 交互流程？RTP 怎么打包 H.264？」岗位对口必考
RTSP：OPTIONS（探能力）→ DESCRIBE（获 SDP：编码/分辨率/SPS PPS）→ SETUP（定传输：UDP 端口对或 TCP interleaved 通道）→ PLAY → RTP 流媒体 → TEARDOWN。
RTP 打包 H.264（RFC 6184）：NALU ≤ MTU 单包直发；超限用 FU-A 分片——1 字节 FU indicator（NAL 头）+ 1 字节 FU header（S/E 起止位）+ 分片数据；序列号每包 +1，时间戳按 90kHz 时钟。
「你项目里零拷贝是怎么落地的？」项目对口
三段：① 解码输出：mppvideodec 输出 DMA-BUF，gst_dmabuf_memory_get_fd 取 fd；② 跨进程：sendmsg + SCM_RIGHTS 把 fd 发给 Qt 进程，OpenGL 以 fd 建 EGLImage 直接采样；③ 录像：fd 作为 AV_PIX_FMT_DRM_PRIME 输入 h264_rkmpp 编码。任一环节断链即退化为用户态 memcpy——这是全项目含金量最高的部分。
「码率控制模式了解吗？」加分项
CBR 恒定：码率稳定可预算，画质波动；VBR 可变：画质稳定，码率随场景波动；ABR 平均：折中。监控常用 CBR/ABR + GOP 对齐（I 帧占码率大头）；智能编码思路：静态场景降帧率/降码率（海康 H.265+ 同思路）。

2.6 调试与性能

「段错误怎么定位？」27届面经
ulimit -c unlimited 开 core dump；gdb ./app core → bt 看调用栈、frame 切帧、info locals 看变量；编译加 -g -O0；或 gdb 里直接 run 复现。更高效：编译加 -fsanitize=address。无 core 的现场用 dmesg 查内核日志 + addr2line 翻译崩溃地址。
「内存泄漏怎么排查？」27届面经·二面
工具：ASan（插桩，最准）、valgrind（慢但全面）。方法：长跑监控 /proc/self/status 的 RSS 是否持续增长；代码层 review new/delete 配对、RAII 封装、智能指针；退出时跑一次 valgrind 报告定位。
「偶发 bug 怎么复现和定位？」27届面经·二面
方法论：① 收敛条件——记录发生时完整上下文（日志/队列深度/时间点），找共性；② 加速复现——压力测试 + 并发 + 长跑 + 随机延迟注入；③ 假设-验证——二分代码版本、加断言缩小范围；④ 修复后加回归。讲一个项目真实案例（如偶发花屏 → 定位 buffer 生命周期 → 引用计数修复）最有说服力。
「系统性能优化做过什么？」已意向面经·二面原题
你的实答（按项目）：① 零拷贝——1080p NV12 一帧约 3MB，全程 fd 传递消除多次 memcpy；② NPU 三核绑定负载均衡；③ 无锁队列降低锁竞争；④ Frame 对象池避免高频分配释放；⑤ RGA 硬件做缩放/格式转换替代 CPU。每条都能展开"优化前 → 优化后"对比。

2.7 手撕代码现场白板/共享屏幕

「手写 strcpy + 追问为什么会崩溃」CSDN 汇总·海康原题
char *my_strcpy(char *dst, const char *src) {
    char *ret = dst;              /* 保存首地址用于返回 */
    assert(dst != NULL && src != NULL);
    while ((*dst++ = *src++) != '\0')
        ;
    return ret;
}
追问要点：① 源目标重叠 → 未定义行为，重叠场景用 memmove 语义；② dst 空间不足 → 越界写，安全场景用 strncpy/strlcpy 并显式置 '\0'；③ src 无 '\0' → 死循环读越界；④ 返回值支持链式表达式；⑤ 先保存 ret 是因为 dst 在循环中移动。
「手写字符串翻转」已意向面经·一面原题
void reverse_str(char *s) {
    size_t n = strlen(s);
    for (size_t i = 0, j = n - 1; i < j; i++, j--) {
        char t = s[i]; s[i] = s[j]; s[j] = t;
    }
}
变体准备：句子单词顺序翻转（两次翻转法：整体翻转 + 逐词翻转）；原地翻转不申请额外空间。

2.9 偶考速览BSP / MCU 向——嵌入式-应用岗出现率低，各背一句话

「驱动 / RTOS 方向偶考题一览」27届面经 / 已意向面经
字符 vs 块设备：字节流顺序访问（串口/LED）vs 按块随机 + 缓存（存储）；驱动核心是 file_operations（open/read/write/ioctl/poll/mmap）。
I2C：两线开漏 + 上拉，7 位地址（写时左移 1 位补 R/W 位——经典坑），支持时钟延展。SPI：四线全双工，CPOL/CPHA 四种模式，无应答机制，速率高于 I2C。
中断上下文：硬中断中不可睡眠/阻塞（无进程上下文），耗时工作放工作队列 / tasklet。
DMA：外设与内存直接传输不占 CPU；视频解码器输出即 DMA-BUF。
jffs2 vs yaffs2：均为 Flash 日志结构文件系统，自带磨损均衡；jffs2 偏 NOR、挂载慢，yaffs2 专为 NAND。
优先级反转：低优先级持锁、高优先级等待、被中优先级间接阻塞 → 优先级继承 / 优先级天花板解决。
看门狗：监控任务检测各线程心跳，全部健康才喂狗，防"卡死仍在喂狗"的假活。
说明：这些题集中在 BSP/驱动岗面经；嵌入式-应用岗主战场是 2.1–2.8。

3.1 项目①：基于 RK3588 的多路智能安防监控系统团队项目 · 你负责视频链路与 IPC 核心

  • 数据与显示：SQLite WAL 模式 6 张业务表多进程安全读写；HDMI 大屏 8 路 OpenGL NV12 纹理渲染（2×4 网格 / 单路全屏）+ DSI 触摸屏 12 功能窗口

3.1.1 项目①深挖预案按真实面经"追问到底"的深度准备

「为什么拆四个进程而不是单进程多线程？」
① 故障隔离：UI 崩溃不拖垮检测核心；② 负载分离：渲染重 IO、推理重计算，独立调优互不干扰；③ 协作边界：团队并行开发。代价是 IPC 开销——用零拷贝把代价压到最低（顺势引出 SCM_RIGHTS）。反问准备："为什么不用容器/微服务？"——嵌入式单机场景，本地 socket + 进程监督足够，引入容器是过度设计。
「DMA-BUF 和 SCM_RIGHTS 的原理？」
DMA-BUF：内核中跨驱动共享缓冲区的标准机制，用户态以 fd 为句柄，VPU / GPU / NPU 都能直接以它作输入输出。SCM_RIGHTS：Unix 域 socket 的辅助消息，sendmsg 时把 fd 放进 cmsg，内核在接收进程安装一个指向同一 struct file 的新 fd。生命周期由 fd 引用计数管理。坑：跨进程后原 fd 仍有效，需约定所有权（谁负责 close）。
「NPU 三核并行怎么做的？」
每个推理 worker 持有独立 rknn context，初始化时按 worker_id 指定 NPU core（0/1/2），帧经 MPMC 队列被空闲 worker 领取，三核同时处理不同帧，吞吐约 3×。追问"多线程共用一个 context 行不行"——run 内部有状态，并发会被串行化反而退化。（按你的实际实现核对表述细节）
「无锁队列怎么实现？」
SPSC ring：预分配数组 + head/tail 两个原子索引，生产者只写 head、消费者只写 tail——单写方原则天然无竞争；release/acquire 内存序保证"数据发布先于索引可见"。容量取 2 的幂（取模换位与加速）。MPMC 用于 worker 池分发。诚实策略：实现若有简化（自旋 + CAS），直说并给出改进方案——比被追问穿帮好得多。
「智能录像为什么用状态机，不逐帧判断？」
逐帧判断会抖动：人一晃就反复开关录像。状态机把时间维度纳入决策——空闲 → 进入 ROI → 停留计时超阈值 → 触发录像 → 离开 → 延时停止 → 免打扰期抑制。防抖、防重复触发、天然支持免打扰。这是"业务规则显式建模"的例子，可迁移到任何事件型系统。
「解码用 GStreamer、编码用 FFmpeg，为什么不统一？」
解码侧 GStreamer 对 Rockchip 插件生态完整（mppvideodec 直接输出 DMA-BUF），多路管线与调度现成；编码侧 FFmpeg 对 GOP / 码率 / Profile 和 MP4 封装控制更细，h264_rkmpp 接受 DRM_PRIME fd 正好接零拷贝。混用不冲突——各取所长，中间以 fd 为"通用货币"。
「8 路并发怎么不丢帧？延迟怎么控制？」
分路独立解码线程 + 帧池；解码与推理经队列解耦削峰；显示端"丢旧帧"策略（渲染跟不上时取最新帧，监控场景可接受跳帧不可接受滞后）。【投递前用实测数据回答此题】
「这个项目你遇到的最难的 bug？」27届面经·验证真伪专用
准备一个真实故事，结构 = 现象 → 排查过程（工具 + 假设）→ 根因 → 修复 → 教训。推荐素材：跨进程 fd 生命周期导致的偶发花屏/崩溃、GStreamer appsink 拿不到 DMA-BUF 的问题、多进程 SQLite 写冲突。细节（日志、参数、耗时）越具体越可信。
